## What this project is
A Python research prototype that classifies phonocardiogram (PCG) heart-sound recordings — normal vs abnormal, multiclass acoustic events, and murmur/outcome — using a search-optimized heterogeneous ensemble over ~138 engineered features across three public dataset families. It is an **academic screening and decision-support prototype**, never a diagnostic tool.

Full task list: `Docs/todo.md`. Work through it in order (Phase → Task, e.g. T09.4), one phase at a time. Do not skip ahead — later phases depend on earlier ones. **Backend and pipeline first**; the dashboard (Part X) starts only after Part IX is complete.

## The frontend rule that matters more than any other

**The client never computes, and never declares, a metric.** Every precomputed number reaches the browser through build-time codegen: `scripts/06_export_frontend_data.py` reads `outputs/`, formats the numbers in Python, and writes `frontend/lib/generated/`. Pages import from `generated/` and nothing else.

No hand-typed metric literal in a page. No client-side rounding. No runtime fetch for anything that already exists on disk. Only live inference (`POST /predict`) crosses the wire at runtime.

This is enforced, not trusted: `scripts/07_check_no_hardcoded_metrics.py` fails the build on any numeric metric literal in `frontend/app/` or `frontend/components/`, and T119.3's displayed-value audit is a hard gate before any screenshot is taken. This rule exists because of a parallel implementation of this same brief that displayed a 95.82% PhysioNet result its pipeline never produced, and a CirCor validation it never ran — analysed in the 2026-08-23 entries in `note.md`.

## The seven non-negotiable research rules
These override convenience, speed, and any instinct to make a result look better. They are the whole reason this project is credible.

1. **No fabricated numbers.** Never hand-type a metric, confusion-matrix cell, or comparison value. Every number in every deliverable is generated by code and traceable to its source CSV/JSON. If a number cannot be generated, it goes in `outputs/missing_outputs_report.txt` with the technical reason — never invented, never silently omitted. That file is created empty in Phase 01 and appended to as gaps arise; it is not written at the end from memory.
2. **Fold safety.** Scaler, imputer, feature selector, and every search run **inside** the training fold. The outer test fold is never seen, never scored during search, never used to fit anything.
3. **No subject leakage.** Where a subject/patient ID exists, group by it. A subject never appears in both train and test. Where an ID cannot be derived, record `subject_derived=False` and say so in the write-up.
4. **Never merge label spaces.** Binary, PASCAL A (4-class), PASCAL B (3-class), CirCor murmur, and CirCor outcome are five separate tasks with five separate targets. Do not merge PASCAL A and B. Do not fold CirCor murmur into the binary task.
5. **Fixed seed 42, everywhere.** Every run records its seed, fold map, hyperparameters, and package versions to the run manifest. Two runs of the same command must produce identical numbers.
6. **Never accuracy alone.** Report sensitivity, specificity, F1, balanced accuracy and AUC for binary; macro-F1 and per-class recall for multiclass. Final model selection prioritises **sensitivity and balanced accuracy**, not accuracy.
7. **Screening language only.** No diagnosis, no treatment, no prescription, no "replaces a doctor". The disclaimer appears in the README, on every dashboard page, and in every generated report.

## Results that look too good are a bug until proven otherwise
If a metric comes back at or near 1.0, **stop and investigate before recording it**. In this project the overwhelmingly likely causes, in order, are: a leaked subject across folds, a scaler fitted on the full matrix, a duplicate recording appearing in both splits, or a label joined on the wrong key. Perfect accuracy is a symptom, not an achievement. Re-verify it independently and write what you found in `Docs/note.md`.

## Known weak points in the source documents

Four things the blueprint and extraction spec get wrong or leave dangerous. All are already handled in `todo.md`; this list exists so they are recognised rather than rediscovered.

1. **EXP-D1 is adult-to-paediatric transfer**, described in the blueprint as testing "compatible" labels. PhysioNet median age 25, 0.3% under 18; CirCor ~98% child/infant. A large drop is expected and is a population effect, not a method failure. Never report it as "our method does not generalize".
2. **The statistical plan is underpowered as written.** Wilcoxon and Friedman over 5 CV folds is n=5 and cannot reach significance in some configurations. Repeated CV (5x5) runs first, and every p-value states its n.
3. **Objective 6 rests on tiny samples.** PASCAL A is 124 records with 19 in one class. The PhysioNet diagnosis track (3,240 records) exists to carry that objective properly — it is not optional decoration.
4. **PASCAL's `artifact` is a recording-quality label, not a cardiac class.** The four-class model must never be described as a four-class *cardiac* classifier.

Also minor: the extraction spec asks for overlapping deliverables (T24/T25/T26 are three views of the same complexity data; G21 and G22 largely overlap). Generate them all — the spec forbids silent skipping — but do not treat the redundancy as a sign something was misread.

## Verified dataset facts — do not re-derive these
Audited 2026-08-22 against the real files. Full detail and the traps involved are in `Docs/note.md`.

| ID | Path | Real contents | Native fs |
|----|------|---------------|-----------|
| D1 PhysioNet 2016 | `dataset/archive (3)` | 3,240 train (a–f) + 301 validation; 2,725 normal / 816 abnormal | 2000 Hz |
| D2 PASCAL A | `dataset/archive (2)/set_a` | 124 labeled + 52 unlabelled | 44100 Hz |
| D3 PASCAL B | `dataset/archive (2)/set_b` | 461 labeled + 195 unlabelled | 4000 Hz |
| D4 CirCor 2022 | `dataset/archive/training_data/training_data` | 942 patients / 3,163 recordings | 4000 Hz |
| — | `dataset/Heartbeat_Sound` | **duplicate** of D2+D3, foldered by class — label helper only, never a training source | — |

All 7,536 files are readable, mono, and uncorrupted. Four traps that will cost a session each if forgotten:
- **CirCor `Outcome` is NOT in `training_data.csv`.** It exists only in the per-patient `.txt` files as `#Outcome: Normal|Abnormal`. Parse the txt files.
- **CirCor's path is doubled:** `archive/training_data/training_data/`. Not a typo.
- **PASCAL set_b CSV filenames do not match disk** (`Btraining_extrastole_127_…` vs `extrastole__127_…`, zero overlap). Use the `Heartbeat_Sound/` folder structure as the authoritative label source.
- **`Heartbeat_Sound/` is a 100% duplicate** (832/832 filename overlap) of set_a+set_b. Including it in training silently doubles the data and inflates every result.

## Testing discipline — the gate rule

**Every phase ends with task `.7`, its [TEST] gate. A phase is not done until its gate passes.** Do not start the next phase on a failing or unrun gate, and never report a phase complete with its gate unchecked.

**Five 🔴 MEGA TEST phases — 29, 52, 76, 104, 120 — sit at the major boundaries.** Each re-verifies everything important built up to that point. Nothing in the following Part begins until a mega test is fully green. They exist because a leakage bug introduced in Phase 12 is cheap to fix at Phase 30 and catastrophic to discover at submission.

Three rules that bind every test:

1. **Never weaken a test to make it pass.** If a gate fails, fix the cause. If the gate itself is wrong, say so explicitly, change it deliberately, and write a `note.md` entry explaining why. Silently relaxing an assertion is the worst possible outcome in this project.
2. **Run it; don't reason about it.** "This should pass" is not a pass. Execute it and report the real output, including failures.
3. **Verify against the actual files, not synthetic input.** A test proving the extractor returns 138 finite values from a synthetic signal says nothing about a 0.76-second PASCAL B recording or a 122-second PhysioNet one. Both exist in this dataset. A generator that writes an empty or all-NaN file has not succeeded — open the output and look at it.
